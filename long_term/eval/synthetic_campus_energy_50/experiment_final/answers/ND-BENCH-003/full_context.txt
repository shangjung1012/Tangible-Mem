根據提供的會議內容，在 ND-013 會議中，團隊針對「資料同意流程」記錄了以下關鍵觀點：

*   **最新決策狀態**：團隊決定將「資料同意流程 (stakeholder data consent workflow)」納入正式設計，並將其作為後續評估或部署的條件之一 (ND-013 / [264])。

*   **問題的性質**：
    *   此議題不僅是單純的技術問題，還涉及資料同意、設備維護以及誰有權覆寫系統建議的權責問題 (ND-013 / [227], [288])。
    *   需要從多個角度看待，因其同時牽涉到能源成本、使用者公平性、現場維護和資料可信度 (ND-013 / [231])。

*   **資料與技術層面的考量**：
    *   有觀點反對僅用平均值處理資料，因為這會忽略尖峰時段和例外事件，導致排程看似完美但在現場卻不可行 (ND-013 / [233], [291], [298])。
    *   團隊發現，根據合成日誌、校園用電資料或現場回報，「資料同意流程」會影響排程品質與操作可行性 (ND-013 / [226])。
    *   現場限制方面，設備並非都會即時回報，因此不能假設資料每分鐘都完整，這點需要寫進下一版實驗設定中 (ND-013 / [244])。
    *   目前最大的挑戰在於確保輸入的資料能穩定地代表現場狀態，而不僅是模型能否運行 (ND-013 / [248])。

*   **評估與使用者互動**：
    *   評估指標應全面，需分開考量節電、等待時間、公平性和使用者信任，避免被單一指標主導 (ND-013 / [230])。
    *   為了讓行政端接受系統建議，儀表板上不能只有一個分數，必須解釋推薦策略的原因 (ND-013 / [228], [229])。

*   **後續行動與結論**：
    *   建議將此問題拆解為資料層、決策層和溝通層來處理 (ND-013 / [270], [300])。
    *   建議先在小範圍（例如兩棟樓和四支充電樁）進行現場試點（field pilot），以利於除錯 (ND-013 / [267], [294])。
    *   會議的暫時結論是，此議題不能只用一個摘要來代表，應將其拆分為可追蹤的觀察、假設、決策和後續行動 (ND-013 / [251], [289])。
