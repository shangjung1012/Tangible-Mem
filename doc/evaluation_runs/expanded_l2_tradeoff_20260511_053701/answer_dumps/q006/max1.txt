根據提供的資料，manager-agent 架構是從現有的單體式腳本（monolithic script）演變而來的，其核心是為了實現關注點分離（separation of concerns）和專業化處理。

演變過程與理由如下：

1.  **架構轉變**：系統架構將從目前的單體式腳本轉變為 Manager-Agent 模型。在這個新模型中，一個中央精簡的 manager 會依序協調多個小型的專業 agent [0429 | L1-0429-108, L1-0429-102]。
2.  **專業化理由**：採用此架構的理由是為了讓處理更專業化、智慧化。每個 agent 都是特定任務的專家（例如計算跳行），而 manager 則簡化為一個單純的調度者，這也使得對整體流程有更好的控制 [0429 | L1-0429-107, L1-0429-114]。
3.  **修正現有實作**：目前的實作被認為有缺陷，因為「manager」也承擔了細微的 agent 類任務。因此，團隊決定需要進行重構，將 manager 的職責簡化為僅分派任務給專業的 agent [0429 | L1-0429-115, L1-0429-109]。
4.  **未來決策**：專案仍面臨一個關鍵的架構決策，即應採用單一 manager-agent 模式還是多 agent 模式 [0429 | L1-0429-119]。

此議題與 `agentic pipeline control` 主題相關 [L2-agentic-pipeline-control]。
