根據我們過去的討論，將逐字稿（transcript）拆分成 segment 或 idea units 主要有以下幾個原因：

1.  **處理上的限制**：最初曾嘗試將完整逐字稿一次性提供給模型處理，但因為上下文長度過大，且難以處理所需的 JSON 輸出，所以放棄了這個方法，轉而採用分塊處理的策略。
    *   來源: `0429 / L1-0429-122`

2.  **維持語義完整性**：採用固定大小的區塊來切分文本，可能會破壞語義的完整性（例如：將一個問題與其答案分開）。因此，我們傾向讓模型根據語義來動態決定區塊大小，形成 idea units。
    *   來源: `0422 / L1-0422-007`

3.  **避免記憶節點內容趨同**：若使用較大的文本區塊來更新多個相關的記憶節點，可能會導致這些節點的內容隨時間變得同質化，失去獨特性。將文本細分為 idea units 有助於避免這個「節點趨同」（node convergence）的問題。
    *   來源: `0429 / L1-0429-125`, `0429 / L1-0429-133`

4.  **捕捉微小細節**：即使是已經切分好的 `segments`，也需要進一步標記成 `idea units`，這是為了能捕捉到 `segments` 內部可能存在的微小但重要的細節。
    *   來源: `0506 / L1-0506-027`

5.  **建立更優越的系統架構**：將逐字稿結構化為 idea units 是我們系統設計的核心部分，這讓我們能在此基礎上建立更高層次的結論，使其優於僅做文本分塊和語義搜索的標準 RAG 基準。
    *   來源: `0429 / L1-0429-019`
