根據提供的會議內容，團隊從使用「分鐘」改為「token」來衡量 dataset 是否足夠，其主要原因是在 `meeting_0429` 的討論中，意識到 **token 才是大型語言模型（LLM）與 agent 研究領域中衡量資料長度的標準單位**，而「分鐘」對於評估模型處理能力來說並不是一個有意義的指標。

演進過程如下：

1.  **初始評估方式 (分鐘)**
    在 `meeting_0429` 會議初期，團隊成員提到目前累積了 5 場會議，總計約 180 分鐘的資料，但不確定這樣的量對於能力很強的 LLM 來說是否足夠。
    *   **來源**: `meeting_0429 / SPEAKER_04 / line range: 4-6`
    > 我們現在累積的data應該是前面有从这个学期开始比较就是有一直focus在研究上的总共有五场然后现在总计的时间大概是180分钟
    *   **來源**: `meeting_0429 / SPEAKER_04 / line range: 10-12`
    > ...以現在LLM来说其实他们能力都蛮强那这样下去做实验不太确定这个5场的内容够不够...

2.  **提出質疑與新標準 (Token)**
    SPEAKER_02 隨即提出質疑，指出用「分鐘」來衡量長度缺乏根據，因為在 LLM 的世界裡，資料長度的極限與定義（特別是 "long context"）是基於 **token** 或字數，而非時間。
    *   **來源**: `meeting_0429 / SPEAKER_02 / line range: 13-16`
    > 在這個地方的話你們說這個長度對於LLM來說這個不是一個問題它是有什麼樣的根據嗎因為這個地方如果你們在講這個專題的時候你就要蠻明確的講說像是就以Large Language Model來說在處理這種會議資料的時候最長就是在多長
    *   **來源**: `meeting_0429 / SPEAKER_04 / line range: 17-18`
    > 對我們有要去嘗試大概多長大概多長是他的極限那我們就是要做是幾個turn還是幾個字他通常算的應該是我覺得應該是看token對應該是看token

3.  **確立新方向**
    SPEAKER_02 強調，團隊應該去查詢目前學術界或業界在 agent 領域如何定義 "long context"，並用這個標準（token 數）來重新評估自身資料集的規模。他們明確指出，agent 的世界裡「沒有分鐘的概念」。
    *   **來源**: `meeting_0429 / SPEAKER_02 / line range: 19-21`

    *   **來源**: `meeting_0429 / SPEAKER_02 / line range: 28-30`

總結來說，這次轉變是為了讓團隊對 dataset 規模的評估更加科學化，並與 LLM 和 agent 研究領域的通用標準對齊，從而能更準確地判斷其資料集是否足以挑戰當前模型的極限。
