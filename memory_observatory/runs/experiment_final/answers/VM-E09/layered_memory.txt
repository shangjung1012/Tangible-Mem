根據提供的會議記錄，團隊從 2026-04-29 開始決定改用 token 而不是分鐘來衡量資料集，主要原因是為了採用一個更精確、且符合大型語言模型（LLM）技術標準的指標來評估資料量是否足夠。

演進過程如下：

1.  **問題浮現 (2026-04-29)**：團隊當時累積了 5 場會議，總計約 180 分鐘的逐字稿。然而，他們不確定這樣的資料量對於 LLM 實驗來說是否足夠 (來源: 0429 / L1-0429-004, L1-0429-042)。

2.  **尋求精確定義 (2026-04-29)**：為了回答「資料量是否足夠」這個問題，會議中提出，使用「分鐘」作為單位是不夠精確的。對於 LLM 而言，處理能力的極限和上下文長度是透過「token 數量」來計算的。因此，團隊需要先去研究在 agent 領域中，大家公認的「長上下文 (long context)」的確切定義是什麼（通常以 token 數為單位）。

3.  **決策 (2026-04-29)**：基於上述討論，團隊決定改變評估資料集規模的指標，不再使用「分鐘」，而是改用一個針對 agent 的「長上下文」的精確定義（很可能是 token 數量）來衡量現有資料。這樣才能準確地評估他們擁有的資料相對於模型能力的規模 (來源: 0429 / L1-0429-001)。

總結來說，從「分鐘」轉向「token」是為了將資料量的評估標準與 LLM 的技術限制和業界慣例對齊，從而更科學地判斷現有資料集是否滿足「長上下文」研究的需求。這個討論也伴隨著解決資料不足的策略，例如考慮使用 LLM 擴增對話，或整合更大規模的真實會議記錄 (來源: 0429 / L1-0429-045, L2-dataset-selection)。
