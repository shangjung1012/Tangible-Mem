演進過程如下：

1.  **早期討論與外部資料集單位**：
    在較早的討論中，團隊在研究外部資料集（如 LOCOMO）時，就已經接觸到以 token 為單位的計算方式。例如，在 0318 的會議中提到 LOCOMO 資料集包含約「26000 個 tokens」（`meeting=0318, lines=1-20`）。這顯示 token 作為衡量單位在他們的參考資料中早已存在。

2.  **初期以「分鐘」衡量自有資料**：
    在 0429 會議的開頭，團隊成員仍然習慣以時間長度來描述他們自己累積的資料量，報告說：「我們現在累積的 data...總共有五場然後現在總計的時間大概是 180 分鐘」（`meeting=0429, lines=1-20, 91-110`）。

3.  **轉換契機：對齊 LLM 的標準**：
    在 0429 的會議中，當團隊成員提出「不太確定這五場的內容夠不夠」時，SPEAKER_02 提出了關鍵的質疑。他指出，用「分鐘」來衡量資料長度對於 LLM 來說可能沒有意義，並要求團隊去了解 AI Agent 領域如何定義「long context」。他強調：「因為這 180 分鐘感覺不是 agent 他們在定義 long 的那個...就沒有分鐘的概念」（`meeting=0429, lines=1-20, 91-110`）。

4.  **達成共識並確立新標準**：
    經過討論，團隊成員意識到 LLM 處理資料是基於 token 數量，而非時間長度。SPEAKER_04 回應道：「他通常算的應該是我覺得應該是看 token 對應該是看 token」（`meeting=0429, lines=1-20, 91-110`）。因此，團隊決定改用 token 作為衡量標準，這樣才能將自己的資料量與學術界公認的「long context」標準進行比較，從而更科學地判斷資料是否充足。
