根據您提供的資料，目前規劃的評估設計以及其從 0318 會議以來的演進歷程如下：

### **目前的評估設計 (以 0429 會議為主)**

目前的計畫是透過一系列的比較和特定問題來驗證記憶系統的成效。

**1. 評估基準 (Baselines) / 消融研究 (Ablation Study):**
為了證明「short term + long term」完整架構的必要性，團隊規劃了消融研究，將與以下幾種基準模型進行比較 (meeting_id: 0429, lines: 121-140)：
*   **只有 RAG 的系統**：直接對逐字稿進行語意向量檢索，沒有額外的資料整理或階層。
*   **只有 Short-term 機制的系統**。
*   **只有 Long-term 機制的系統**。
*   **完整的系統 (Full system)**：包含 Working, Short-term, Long-term 三層記憶架構。

**2. 評估問題類型與指標 (Metrics):**
評估用的問題主要分為三種類型，旨在測試不同層面的記憶能力 (meeting_id: 0429, lines: 106-125, 16-35)：
*   **Short-term Correctness**：確保模型能正確回答關於近期會議內容的問題。
*   **Long-term Evolution**：針對某個研究主題，要求模型闡述其「從過去到現在完整的演進」。這個問題的評估重點是**正確率與完整性**，模型不能漏掉任何一場相關會議的討論重點，也不能自己編造內容 (meeting_id: 0429, lines: 91-110)。
*   **Decision Reasoning**：詢問「為什麼我們現在做這個決定」，測試模型是否能理解並回溯導致某個決策的歷史討論脈絡。

此外，還有一個特別的評估點：
*   **遺忘機制 (Fade-out) 的測試**：評估模型是否能區分重要與不重要的資訊。在一般對話中，模型應避免提及那些已經過時或不重要的「inactive ideas」，但當透過特定指令 (如 function call) 查詢時，又能證明這些記憶仍然存在於 long-term memory 中，只是被暫時擱置。這是一個過去 agent 較少被測試的面向 (meeting_id: 0429, lines: 106-125, 16-35)。

### **評估設計的演進歷程**

評估方法的設計是逐步演進的，從早期參考文獻，到形成具體的計畫：

1.  **早期探索階段 (0307)**：
    團隊在初期就意識到需要證明新架構的價值，而不只是「用一般的 LLM 就好」。當時的想法是參考其他論文如何進行評估，並推測可能需要設計特定問題來展示 short-term 和 long-term memory 的存在與效果 (meeting_id: 0307, lines: 31-50)。

2.  **文獻回顧階段 (0318)**：
    在此階段，團隊主要在回顧相關論文，例如一篇 UCSD 的 arXiv paper。他們注意到該論文使用了 Gemini、Visual RAG 等模型，並讓 LLM 擔任評審 (judge) 的角色，同時也計算了儲存大小 (storage size)。這個階段主要是吸收外界的做法，但尚未形成自己專案的具體評估方案 (meeting_id: 0318, lines: 46-65, 61-68)。

3.  **初步構想階段 (0325)**：
    團隊開始討論具體的評估方式。當時提出了一個初步想法：將「沒有三層架構的 baseline」（即把所有逐字稿直接塞給模型）作為比較對象。評估方法則是使用前 N 次的會議內容來建立記憶，然後用第 N+1 次的會議來測試模型回答的表現，並與真實答案進行比對 (meeting_id: 0325, lines: 166-185)。

4.  **詳細計畫階段 (0429)**：
    到了這個階段，評估計畫變得非常具體。早期的模糊想法演變成了明確的**三類評估問題**（Short-term, Long-term Evolution, Decision Reasoning）和一個包含 **RAG-only、Short-term-only、Long-term-only** 的**消融研究**計畫。此外，還加入了對**遺忘機制 (fade-out)** 的創新測試，以更全面地驗證記憶系統的複雜功能 (meeting_id: 0429, lines: 106-125, 121-140)。

總結來說，評估設計從最初「我們該如何證明？」的開放式問題，經過文獻參考與團隊討論，逐步聚焦，最終在 0429 的會議中確立了一套包含多種基準比較和三類核心問題的詳細評估框架。
