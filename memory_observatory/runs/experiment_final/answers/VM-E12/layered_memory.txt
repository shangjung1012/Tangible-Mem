根據提供的資料，關於先進行記憶體更新（update）後處理檢索（retrieve）的原因，以及後續檢索設計的演進如下：

### 為什麼先做 Update，晚點做 Retrieve？

專案初期的實作計畫是先建立記憶體的更新（update）方法，之後才處理如何從中檢索（retrieve）。這是因為團隊需要先確保資訊能夠被有效地儲存和結構化，才能進一步設計如何取用這些已儲存的記憶來生成有意義的輸出。

*   **早期規劃 (2026-03-07)**：團隊在當時指出，系統的設計主要集中在「update memory」的部分，而「如何從記憶取出來（retrieve）」的機制尚未設計。當時的計畫是先分別建立三種記憶體類型（long-term, short-term, working）的更新方式，然後再處理如何取用它們 (L1-0307-013, L1-0307-024)。

### Retrieve（檢索）設計的後續演進

在確立了更新機制後，團隊很快將重點轉向檢索，並視其為核心挑戰。其設計演進如下：

1.  **確立檢索為核心問題 (2026-03-25)**：團隊決定將研究重點放在檢索問題上。當時的核心挑戰被定義為：Agent 應如何權衡與組合來自三種不同記憶體（working, short-term, long-term）的資訊，以生成最佳輸出 (L1-0325-056, L1-0325-058)。

2.  **分層檢索架構的提出 (2026-04-08)**：檢索流程被設計為一個分層的過程。首先將查詢與最精細的 L1 節點進行比對，然後取回匹配的 L1 節點及其對應的父層 L2 和 L3 摘要。這樣的設計旨在同時提供具體的細節（L1）和高層次的上下文（L2/L3）(L1-0408-006)。

3.  **引入動態分數以輔助檢索 (2026-04-08, 2026-05-06)**：
    *   為了處理主題的重現，系統採用了時間衰減機制。記憶節點的「recency」分數會隨時間衰減，但會根據其初始的「importance」分數設定一個下限值（floor），以防止重要的舊記憶完全消失，確保在相關主題重現時能被重新檢索 (L1-0408-007)。
    *   後來此設計進一步細化：決定將「importance」分數保持靜態，作為節點創建時的歷史重要性參考。記憶的活躍度與衰減則由一個獨立的「activation」參數處理，這同樣確保了高重要性的節點不會輕易消失 (L1-0506-030)。

4.  **檢索與遺忘機制的整合 (2026-04-22)**：系統的遺忘機制與檢索緊密相關。記憶會根據當前的相關性進行檢索，舊的主題會被「遺忘」，除非它們再次變得相關。同時，為了防止關鍵資訊遺失，重要性分數高於特定閾值的記憶將永遠不會淡出，確保其可被檢索 (L1-0422-042, L1-0422-040)。

5.  **最新的實作狀態 (Current Implementation State)**：
    目前的檢索機制被稱為**「證據優先的分層檢索 (evidence-first layered retrieval)」**。此流程從 L1 證據種子（L1 seeds）開始，然後擴展到相關的 L2、子 L2（child-L2）以及 L3 的導航上下文。這證實了早期（4月8日）提出的分層檢索設計已被採納並實作。
