根據提供的會議內容，Long-term memory（長期記憶）的架構演進可以整理如下：

### 1. 早期概念：長短期記憶分離

最初的討論將記憶系統區分為短期（Short-term）與長期（Long-term）兩個獨立的架構。

*   **Short-term Memory (STM)**：設計用於儲存近期（例如最近三次）會議的詳細資訊，如同人腦在對話中會使用到的即時記憶。
*   **Long-term Memory (LTM)**：設計用於捕捉長時間（例如一年）的研究脈絡、架構變化、研究目標與里程碑（milestone）等較為粗略、宏觀的總結。此階段的 LTM 概念較為抽象，主要強調其功能是為了避免將所有會議細節都儲存起來。

**(來源: meeting: 0307, lines: 31-50)**

### 2. 中期具體化：以物件為基礎的記憶 (Object-based)

為了實現長期記憶，團隊將其具體化為一個由「記憶物件 (memory object)」組成的系統。每一次會議的逐字稿會被處理，抽取出特定類型的資訊，並轉換成結構化的物件。

一個典型的長期記憶物件包含以下欄位：
*   **Type**：物件的類型，例如 `Decision`、`To-Do`、`Method Change` 等。
*   **Content**：根據 `Evidence` 總結出的精簡內容。
*   **Evidence**：原始逐字稿中對應的段落內容。
*   **Related Topics**：用於檢索的相關關鍵字。
*   **Object ID**：可以追溯回原始錄音檔或逐字稿的唯一識別碼。

**(來源: meeting: 0422, lines: 91-110)**

### 3. 演進為階層式架構：L1/L2/L3 模型

基於物件的記憶進一步發展為一個三層的階層式（hierarchical）架構，以管理不同精細度的資訊。

*   **L1 (最底層)**：最精細的層級。L1 節點是從單次會議中提取出的具體 idea unit 或 object，內容最詳細，可以直接對應到逐字稿的特定段落。
*   **L2 (中層)**：對 L1 節點的總結。最初的設計是每四次會議的 L1 內容會被彙整成一個 L2 節點，類似「月度總結」。
*   **L3 (最高層)**：最宏觀的層級。L3 節點是對所有 L2 節點的再總結，呈現整個專案或系列會議的最高層次架構與大方向。

當使用者查詢時，系統會先找到相關的 L1 節點，並連同其所屬的 L2 和 L3 節點一起提供，讓使用者既能看到細節，也能理解其所在的整體脈絡。

**(來源: meeting: 0422, lines: 121-140; meeting: 0408, lines: 31-50)**

### 4. 最新討論：階層架構的兩種實現路徑

在最近的討論中，團隊探討了兩種不同的 L1/L2/L3 架構生成方式，顯示了設計思維的進一步演化：

*   **路徑一：以時間／會議為單位 (Time-based)**
    *   **描述**：此架構嚴格按照時間順序組織。每一次會議產生一組 L1 節點。累積四次會議後，會生成一個新的 L2 節點來總結這四次會議。不同 L2 節點之間沒有直接關聯。
    *   **運作方式**：這是一個增生式的過程，新的會議只會產生新的節點，而不會去更新過去的節點。
    **(來源: meeting: 0506, lines: 46-65)**

*   **路徑二：以主題為單位 (Topic-based)**
    *   **描述**：這是一個更動態、以主題為核心的圖狀（graph-like）結構。L3/L2 作為高層次的主題（如「時間考量」、「活動類型」），L1 則是該主題下的具體討論點。
    *   **運作方式**：當新的會議內容進來時，系統會判斷其是否與現有的 L1 節點相關。
        *   **若相關**：則**更新 (update)** 該 L1 節點，加入新的時間戳和討論內容，並提高其 `recency`（新近度）分數。這樣可以追蹤同一個議題在不同會議中的演變。
        *   **若不相關**：則在對應的主題下**創建 (create)** 一個新的 L1 節點。
    *   這種方式的優點是能夠清晰地呈現一個特定議題的演進歷史（trajectory）。
    **(來源: meeting: 0506, lines: 61-72)**

總結來說，Long-term memory 的架構從最初模糊的長短期分離概念，演進到以結構化「物件」為基礎的儲存方式，再進一步發展成 L1/L2/L3 的階層模型。最新的討論則聚焦於這個階層模型應該是以「時間」為軸線增生，還是以「主題」為核心進行動態更新，這兩種路徑反映了團隊對如何更有效地追蹤議題演變的不同思考。
