根據提供的會議記錄，標準的 RAG（檢索增強生成）或 full transcript baseline 不足以處理研究會議記憶，主要原因如下：

### 1. 無法處理資訊的時序性與演進脈絡

標準 RAG 依據語意相似度檢索，但無法理解資訊隨時間的演進、被推翻或被遺忘的狀態。

*   **早期討論 (L1 Evidence Seed)**:
    *   團隊指出，若單純使用 RAG，當一個主題在多次會議中被提及，RAG 會將所有相關的片段都找出來，但無法分辨其間的演進關係。例如，一個議題可能被討論了五次，但在最後一次會議中被決定放棄，RAG 無法理解這個「不要了」的最終決策，只會回傳所有相關的討論片段 (meeting 0325, SPEAKER_01, line range: 425-430)。
    *   研究會議中常有探索後被放棄的「死掉的 topic」。目前的 RAG 或一般語言模型很難抓出「某個主題曾被提及，但後來決定不做，以及為什麼不做」的完整脈絡 (meeting 0325, SPEAKER_02, line range: 431-436)。

*   **近期演進 (L2 Evolution Context)**:
    *   團隊進一步提出，他們的系統希望做到「有意識的遺忘 (fade out)」。有些舊的、不重要的資訊在一般對話中不應該被主動提起，但它又不能完全消失，因為可能在特定情境下需要被重新檢視。標準 RAG 沒有這種區分記憶活躍程度的機制 (meeting 0429, SPEAKER_02, line range: 147-156)。
    *   其他論文提到的遺忘機制，通常是直接從資料庫中刪除資料，這意味著資訊永久遺失。而團隊的設計是讓資訊的活躍度（或 `recency`）降低，但如果後續會議再次頻繁提及，它的分數會回升，重新變為活躍記憶 (meeting 0429, SPEAKER_04, line range: 169-174, 183-186)。

### 2. 缺乏結構化的記憶層次與精細度

Full transcript 或簡單切塊的 RAG 將所有資訊視為同一層級，缺乏對會議內容的結構化理解，難以抓到重點。

*   **早期討論 (L1 Evidence Seed)**:
    *   團隊討論了 long-term memory 的架構，認為它應該是粗略地抓住整個研究脈絡、目標和主題的變化，而不是像 short-term memory 那樣記錄所有瑣碎的細節 (meeting 0307, SPEAKER_02, line range: 100-104)。

*   **近期演進 (L2 Evolution Context)**:
    *   最新的系統設計中，記憶被分成了 L1、L2、L3 三個層次。L1 是從單次會議中提取出的最精細物件（如 decision, to-do），L2 是數次會議（如每月）的總結，L3 則是最高層級、橫跨所有會議的整體研究脈絡。這種階層式結構讓 agent 在檢索時，不僅能找到細節（L1），還能一併帶出其所屬的上下文脈絡（L2, L3）(meeting 0408, SPEAKER_03, line range: 84-88; meeting 0408, SPEAKER_00, line range: 90-95)。
    *   相較之下，RAG 只是簡單地將逐字稿「切塊」，然後用語意相似度尋找，缺乏這種多層次的結構化整理 (meeting 0429, SPEAKER_01, line range: 219-223)。

### 3. 無法有效過濾無關或瑣碎的資訊

直接處理 full transcript 或固定切塊會納入大量與研究主軸無關的閒聊或不重要的資訊。

*   **近期演進 (Latest Retrieved Stage)**:
    *   團隊提到，透過他們設計的 `tool calling` 和 `idea unit` 切分方法，可以過濾掉如「誰還沒來」或閒聊等不必要的資訊。而傳統的固定切塊方法則會將這些無用資訊也一併存入記憶中 (meeting 0429, SPEAKER_01, line range: 232-235)。
    *   在處理逐字稿時，團隊會先將其切分為 `segment`（討論話題），再從中抽取 `idea unit`（觀點），並透過 `type agent`（如 decision, to-do）進行標註。這個過程本身就是對原始資訊進行結構化和過濾，這是 RAG 或 full transcript baseline 所沒有的 (meeting 0506, SPEAKER_01, line range: 110-120, 203-209)。

總結來說，標準 RAG 和 full transcript baseline 缺乏對**時間脈絡**、**結構層次**和**資訊重要性**的理解，它們將會議記錄視為一個扁平、靜態的資料庫，這與研究會議高度動態、不斷演進的特性不符。
