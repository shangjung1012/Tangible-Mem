根據提供的會議內容，將逐字稿（transcript）拆分成多個片段（segment / chunk）是為了處理過長的文本。

在 `meeting 0318` 中，團隊討論了一篇 2024 年的論文，該論文處理長文本（Long Context）的方法就是將其拆分。具體來說：

*   **目的**：為了處理單一模型無法一次性處理的長篇文章或對話紀錄。
*   **方法**：將長文「切成一個 chunks」，然後讓每一個 agent 負責一個 chunk 的摘要（summary）。後續的 agent 在處理自己的 chunk 時，還會參考前一個 agent 產出的內容，以此序貫地處理完整個長文。
*   **來源**：`meeting 0318`, SPEAKER_01 提到：「他就是還是一個大長的文章，那他們做法是說，就是把一個長文直接把它切切切切切，切成一個 chunks，然後每一個 agent 他是負責一個 chunk 的 summary。」

會議中也提到了這種拆分方式的潛在問題，例如，如果隨機切割，可能會將一句話從中間斷開，導致語意不完整（`meeting 0318`, SPEAKER_01）。
