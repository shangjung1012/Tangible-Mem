根據提供的資料，我們將 transcript 拆分成 segment 或 idea units 主要有以下幾個原因：

1.  **提升處理品質**：最初的作法是將整份 transcript 一次性丟給 LLM 處理，但後來發現這樣處理大型文件會導致標籤品質不佳 (poor labeling)。因此改為兩階段作法：先將文本切成較小的「idea units」，再對這些單位進行處理和標記。
    *   來源：`[0408 | L1-0408-017]`

2.  **確保處理的完整性**：採用先切分 idea units 再逐一處理的結構化流程，可以強迫系統檢查每一個單位是否與記憶相關，避免系統自行判斷而跳過某些潛在的更新，確保每個 idea unit 都被檢查到。
    *   來源：`[0429 | L1-0429-125]`, `[0429 | L1-0429-136]`

這個決策最終演變成一個兩步驟的工作流程：首先，一個 `read_segment` 的功能會將 transcript 切割成 idea units 的 JSON 陣列；接著，一個 `update_memory` 的功能會遍歷這些 units，為每一個 unit 呼叫 API 來檢查相似性並更新記憶。
*   來源：`[0429 | L1-0429-126]`
