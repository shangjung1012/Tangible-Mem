根據提供的資料，將 transcript 拆分成 segment 或 idea units 的主要原因如下：

1.  **避免處理整個文件導致的品質不佳**：最初嘗試將整個 transcript 一次性丟給 LLM 處理，但發現這樣做會導致輸出品質不佳，例如在標籤（labeling）時效果很差。
    *   來源：[0408 | L1-0408-017], [0408 | L1-0408-013]

2.  **解決 Context 過大的問題**：將整個 transcript 一次性處理，會導致 context window 變得太大，特別是在要求模型輸出固定的 JSON 格式時，會產生問題。因此放棄了這種做法。
    *   來源：[0429 | L1-0429-158]

3.  **確保處理的完整性**：採用先將 transcript 分割成 idea units，再逐一處理的結構化方法，可以強迫系統檢查每一個 unit 是否與記憶相關，從而避免系統自行決定跳過某些潛在的更新。
    *   來源：[0429 | L1-0429-125]

4.  **提高主題分割的可靠性**：過去曾嘗試讓 LLM 自行從大段文字中分割主題（top-down），但發現這樣產生的主題數量不穩定且不可靠。因此改為更細緻的處理方式。
    *   來源：[0429 | L1-0429-069]

總結來說，將 transcript 拆分是為了解決一次性處理長文本時遇到的品質、技術限制和可靠性問題，並確保記憶更新的過程更為全面和穩定。而「idea unit」被確立為記憶更新最基本的原子單位。
*   來源：[0506 | L1-0506-016]
