根據提供的資料，將 transcript 拆分成 segment 或 idea units 主要有以下幾個原因：

1.  **提升大型語言模型（LLM）的處理精準度並避免產生幻覺**：
    直接將很長的逐字稿一次性丟給 LLM 處理，可能會導致標記效果不佳（"標得非常不 OK"）甚至產生幻覺（hallucinate），即模型會提及內容中不存在的東西。將文本切分成較小的單位，可以讓 LLM 在更少、更精準的上下文中進行分析，從而提升處理結果的準確性。
    *   **來源**: `meeting=0408`, `lines=52-60`

2.  **實現更結構化、可控的處理流程（Manager-Agent 架構）**：
    將 transcript 拆分成 idea units 是實施 Manager-Agent 工作流程的基礎。在這個架構中，「Manager」負責分派任務，而各個「Agent」則處理特定的工作。Idea units 作為標準化的資訊單元，在 Manager 和 Agent 之間傳遞。例如，Manager 可以先呼叫一個 Agent 將逐字稿切分成 idea units 陣列，然後再將這個陣列傳遞給另一個 Agent 來執行更新記憶體的任務。這種方式讓整個處理流程更清晰、更易於控制與管理。
    *   **來源**: `meeting=0429`, `lines=316-323`, `lines=331-335`

3.  **便於執行後續特定任務（如下標籤、更新記憶）**：
    拆分出來的 idea units 可以作為後續處理步驟的基本單位。例如，可以針對每一個 idea unit 去執行特定任務，如：
    *   **下標籤**：先將長文切成 idea unit，再對每個 unit 下標籤。
        *   **來源**: `meeting=0408`, `lines=60-61`
    *   **更新記憶**：將逐字稿切成 idea units 的陣列後，可以逐一（loop through）檢查每個 unit，判斷是否需要更新記憶體。
        *   **來源**: `meeting=0429`, `lines=287-288`, `lines=294-295`
