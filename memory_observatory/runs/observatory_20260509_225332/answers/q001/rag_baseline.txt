根據提供的會議記錄，將 transcript 拆分成 segment 或 idea units 主要有以下幾個原因：

1.  **提升大型語言模型（LLM）處理的精準度與避免錯誤**：
    *   過去的經驗顯示，若將完整的逐字稿直接整段丟給 LLM 處理，可能會得到不理想的結果。例如，直接處理長篇內容曾導致標記效果不佳（"標得非常不 OK"）甚至產生幻覺（hallucinate），即模型可能會提及內容中根本不存在的東西。
    *   將內容切分成較小的單位（如 idea units），可以讓 LLM 在較少的上下文（Context）中處理，這有助於產生更精準的內容。
    *   因此，將切分視為一種必要的前處理步驟，以確保後續處理的品質。
    (來源: `rag-0408-L46-L65`)

2.  **建立結構化、可控制的處理流程**：
    *   將複雜任務拆解成多個步驟，可以讓整個處理流程更加清晰且可控。例如，可以設計一個「Manager-Agent」的架構，由 Manager 負責分派任務，而由特定 Agent 專門處理特定工作。
    *   在這個架構下，第一步可能是呼叫一個 Agent 將逐字稿切分成 idea units。這個 Agent 的輸出（一個包含 idea units 的陣列）會成為下一個 Agent（例如「更新記憶體」的 Agent）的輸入。
    *   這種作法確保了流程的確定性，例如，如果切分出三個 idea units，程式就會明確知道需要執行三次更新，而不是讓模型自己決定要不要更新，從而提升了對流程的控制能力。
    (來源: `rag-0429-L316-L335`, `rag-0429-L286-L305`)

總結來說，將 transcript 切分成 idea units 是一個重要的前處理步驟，旨在提高 LLM 的處理精準度，並建立一個更模組化、可控的自動化工作流程。
