根據提供的資料，將 transcript 拆分成 segment 或 idea units 主要有以下幾個原因：

1.  **避免一次處理整個大型文件導致的品質不佳問題**：
    最初的作法是將整份 transcript 一次性地交給 LLM 處理，但後來發現這樣處理大型文件會導致標籤品質不佳。因此，團隊決定改變作法，先將文字分段成較小的「idea units」，再對這些單位進行處理和標籤，以提升品質。
    (來源: L1-0408-017)

2.  **確保每個 idea unit 都被檢查，避免遺漏潛在的更新**：
    採用一個結構化的兩步驟流程——先分段，再逐一處理——可以強制系統檢查每一個 idea unit 與記憶庫的關聯性。這樣可以確保 transcript 的每個部分都被評估到，不會有任何潛在的更新被隨意跳過或遺漏。
    (來源: L1-0429-125, L1-0429-136)

3.  **建立更結構化且可預期的工作流程**：
    團隊決定實施一個明確的兩步驟工作流程：第一步是 `read_segment` 函式，負責將 transcript 切割成 idea units 的 JSON 陣列；第二步是 `update_memory` 函式，會遍歷這些 units，為每一個 unit 呼叫 API 檢查相似性並更新記憶。這個作法讓整個記憶更新的過程更加清晰和結構化。
    (來源: L1-0429-126)

此外，會議中也曾提議使用 LLM 來根據主題的連續性，將 transcript 預先分割成有凝聚力的 idea units，作為固定行數分段的替代方案，顯示團隊持續在優化分段的方法。 (來源: L1-0422-009)
