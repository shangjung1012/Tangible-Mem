根據提供的資料，manager-agent 架構的出現是為了解決一個更早、更簡單的循序（sequentially）agent 模型所遇到的問題。

演變過程如下：

1.  **初始模型**：有一個處理長篇文章的 agent 模型，作法是將長文切成許多小區塊（chunks），每一個 agent 負責處理一個 chunk 的摘要。這個過程是循序的，第二個 agent 在處理自己的 chunk 時，需要讀取第一個 agent 產出的摘要，依此類推，資訊一路向下傳遞 (meeting 0318 / SPEAKER_01)。

2.  **初始模型的問題**：
    *   **缺乏全域理解**：每個 agent 只知道自己負責的 chunk 和前一個 agent 傳來的摘要，沒有一個整體的、全域的理解。因此有人提出應該要有一個「共享黑板」（shared blackboard）的概念 (meeting 0318 / SPEAKER_01)。
    *   **隨機切分問題**：文章是隨機按大小切分的，可能會將一句話切成兩半，導致 agent 無法理解文意 (meeting 0318 / SPEAKER_01)。

3.  **Manager-Agent 架構的提出**：為了解決上述問題，後續的架構中出現了 **manager agent** 的角色。這個 manager agent 會接收所有 worker agent 處理完的資訊，並進行最終的整合，以回答問題或達成特定任務，從而建立一個更全面的理解 (meeting 0318 / SPEAKER_01)。
