根據提供的資料，我們之所以要把 transcript 拆分成 segment 或 idea units，主要有以下幾個原因：

1.  **提升精準度與避免模型幻覺 (Hallucination)**：
    直接將整份很長的逐字稿丟給大型語言模型（LLM）處理，會導致結果不佳。先前在分析影片時發現，若沒有先做切分，模型標記的結果「非常不 OK」、「非常不準」，甚至會開始產生幻覺，也就是說出文本中根本不存在的內容。因此，將文本切成較小的單位，可以讓模型在較少的上下文（Context）中處理，產生的內容可能會更精準。
    (來源: `meeting=0408`, `lines=46-65`)

2.  **建立可控制的處理流程**：
    將逐字稿切分成 idea units 是一個重要的前處理步驟，能讓後續的記憶更新流程更加結構化。與其讓模型像個「黑箱」一樣一次性處理所有資訊，不如先將其拆分為 idea units，然後再針對每一個 unit 執行後續任務（如下標籤、尋找關聯記憶等）。這樣可以確保流程中的每一步都是明確且可控的。
    (來源: `meeting=0408`, `lines=61-80`; `meeting=0429`, `lines=286-305`)

3.  **便於實現 Agent/Manager 架構**：
    將任務拆解後，可以讓不同的 Agent 專門處理特定的步驟。例如，一個 Agent 專門負責將逐字稿切分成 idea units，另一個 Agent 負責分析每個 idea unit。Manager 的角色則是負責分派這些任務並串連整個流程。這種分工可以讓每個 Agent 更精緻地處理自己的任務，也讓整個系統的流程更加清晰和易於管理。
    (來源: `meeting=0429`, `lines=316-335`; `meeting=0429`, `lines=301-320`)
