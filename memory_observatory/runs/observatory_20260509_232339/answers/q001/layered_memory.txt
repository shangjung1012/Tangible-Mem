根據提供的資料，將 transcript 拆分成 segment 或 idea units 主要有以下幾個原因：

1.  **避免 Context 過大及提升處理品質**：
    *   最初嘗試過將整個 transcript 一次性處理，但發現這樣會導致 context window 過大，特別是在要求模型輸出固定格式（如 JSON）時會產生問題。 (來源: 0429 / L1-0429-158)
    *   一次處理整個大型文件也被認為會導致較差的標籤結果 (poor labeling)。因此改為先將文本切成較小的「idea units」，再對這些單位進行標記。 (來源: 0408 / L1-0408-017)

2.  **確保處理的完整性與可靠性**：
    *   讓大型語言模型（LLM）自行從大段文本中切分主題，會產生數量不穩定且不可靠的結果。 (來源: 0429 / L1-0429-069)
    *   採用先切分 idea units 的結構化方法，可以強制系統檢查每一個單位是否與記憶相關，從而避免系統自行決定跳過某些潛在的更新，確保了處理的完整性。 (來源: 0429 / L1-0429-125)

總結來說，從一次性處理整個 transcript 的方式，轉變為先切分成 idea units 再處理的兩階段作法，是為了克服 LLM 處理長文本時的技術限制、提升輸出品質與可靠性，並確保所有相關資訊都能被完整捕捉。
